The current TASE_QP baseline solves the strict six-variable, twelve-constraint problem `min 0.5 qdotᵀqdot`, `J qdot = xdot_c`, `lower <= qdot <= upper`. It adds no hierarchy, slack, or extra regularization. The adapter marks itself `offline_only=true`, `live_eligible=false`; its offline `NativeContactQp` deadline is disabled. Its default outer config has a `5.0 N·s` integral cap and `delay_T_s=0.004 s`, which do not match current A's `1.0 N·s` or the live RNN's actual-dt delay. Those defaults must be explicitly overridden in a matched replay.

The [sealed confirmation-A input audit](tase_qp_replay_confirmation_a_missing_fields_20260923.md) confirms that current traces lack the per-tick outer twist, dt, reference time, and PATH-origin RNN state required for an exact QP-on-RNN replay. The QP table below is therefore a decision sheet, not a measured QP result. Strict task hierarchy is supported as a general method by [Escande, Mansard and Wieber (IJRR 2014)](https://journals.sagepub.com/doi/10.1177/0278364914521306); that paper does not prescribe numerical values for this UR10e bench.
