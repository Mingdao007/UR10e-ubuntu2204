The existing R006 scoped runtime injection rejected YieldContactProvider before constructing a control because its accepted type was only ContactCommandProvider. The same existing injection now accepts the two explicitly named provider classes. Dedicated contact TP program checking, exact prepared instance binding, one-time consumption, preparation-before-ARM, and process-local injection ownership are unchanged. Arbitrary duck-typed objects remain rejected. No second writer, new transport or active robot route was introduced.

Focused checks exercise both supported provider types, wrong package rejection, provider substitution, one-time consumption and unknown-type rejection. Current model/route binding still needs proper closure before physical execution.

A related snapshot identity omission is fixed: YieldContactRuntime now binds the expanded URDF text SHA in addition to calibration identity. Two model sources with the same calibration string can no longer restore each other's runtime snapshot. Existing snapshots from the older identity intentionally require their recorded code; they are not silently promoted. This affects the measured-observation runtime identity, not native equations, gains, QP limits or offline contact-yield simulation receipts. A test checks rejection before any target state mutation. It does not establish physical model correctness.
